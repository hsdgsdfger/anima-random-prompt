## 1. 定位与边界

| 项 | 内容 |
| --- | --- |
| 做什么 | 在 ComfyUI 里产出「一整段可用提示词」：正向 + 负向 + 档位 + 报告 |
| 不做什么 | 不出图、不评估出图质量、不读写 Anima Wardrobe V6、不联网、不引第三方包 |
| 卖点 | 随机但自洽（45 场景包互斥校验）；可控可复现（档位 / 种子 / 槽位权重 / 覆盖文本） |
| 依赖 | 仅 `PromptServer` + 标准库 |

## 3. 节点接口

### 3.1 基本信息

| 项 | 值 |
| --- | --- |
| 类名 | `PromptForgeRandom` |
| 显示名 | `Prompt Forge 随机提示词（中文）` |
| 分类 | `AnimaDecouple/Prompt Forge` |
| 输出 | `positive` / `negative`，均为 `STRING`（v0.1.2 起收成一正一负，档位信息打到控制台） |
| 前端目录 | `WEB_DIRECTORY = "./web"` |
| 输入槽 | `role_prompt`（`STRING`，`forceInput: true`，默认空串） |
| 版本 | `__version__ = "0.12.0"` |

### 3.2 必填参数（12 个，顺序未变）

| 参数 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `level` | 下拉 | `sfw · 全年龄` | sfw / suggestive / explicit / hardcore / extreme / any |
| `seed` | INT | `-1` | `-1` 每次重抽；`>=0` 可复现 |
| `tag_cap` | INT | `0` | 总标签上限，`0` = 自动（Lv0–Lv1 28 / Lv2+ 32） |
| `base_prob` | FLOAT | `0.65` | 可选槽位的基准出现概率 |
| `slot_weights` | STRING | 空 | 槽位加权 JSON，0 = 关掉该槽位 |
| `role_mode` | 下拉 | `不指定` | 不指定 / 随机 / 指定 |
| `role_name` | STRING | 空 | 指定模式下的角色名或 danbooru tag 片段 |
| `role_works` | STRING | 空 | 按作品限定随机角色，`|` 分隔 |
| `quality_prefix` | STRING | `masterpiece, best quality` | 质量前缀文本 |
| `artist_on` | BOOLEAN | `false` | 是否随机带一个画师标签 |
| `negative_on` | BOOLEAN | `true` | 是否同时输出负面提示词 |
| `extra_body` | STRING | 空 | 手写补充，拼在正向末尾 |

### 3.3 可选参数（8 个）

| 参数 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| `quality_on` | BOOLEAN | `true` | 是否加质量前缀 |
| `scene_mode` | 下拉 | `场景成套 · 现实逻辑` | 场景成套 / 自由随机 |
| `template_override` | STRING | 空 | 覆盖文本；工作台勾选/套用即写这里 |
| `random_each_run` | BOOLEAN | `true` | 每次运行重新随机（忽略固定 `seed`） |
| `override_mode` | 下拉 | `直通` | **v0.12 新增**，追加在末尾：`直通` / `混合` |
| `role_prompt` | STRING | 空 | **v0.12 新增**，`forceInput`，左侧连线接入角色提示词 |
| `appearance_follow` | BOOLEAN | `true` | **v0.12.1 新增**：角色输入非空时，发型/发色/面部/瞳色/身材让位 |
| `outfit_follow` | BOOLEAN | `false` | **v0.12.1 新增**：角色输入非空时，服装/配饰也让位 |

> 控件顺序是契约：`override_mode` 追加在 `random_each_run` 之后，是第 17 个控件，旧工作流 `widgets_values` 不串位。
> `role_prompt` 是 `forceInput`，不产生 widget，不进 `widgets_values`，但会改变序列化 `inputs`。

### 3.3.1 控件中文标签

画布上的控件名由 `web/prompt_forge_v6.js` 的 `LABELS` 映射为中文，序列化键名仍是英文：

| 键 | 中文标签 |
| --- | --- |
| `level` | 档位 |
| `seed` | 随机种子 |
| `tag_cap` | 标签上限 |
| `base_prob` | 基础概率 |
| `slot_weights` | 槽位权重（JSON） |
| `role_mode` | 角色模式 |
| `role_name` | 角色名 |
| `role_works` | 限定作品 |
| `quality_prefix` | 质量前缀 |
| `artist_on` | 加画师标签 |
| `negative_on` | 输出负面词 |
| `extra_body` | 补充描述 |
| `quality_on` | 加质量前缀 |
| `scene_mode` | 场景模式 |
| `template_override` | 模板覆盖文本 |
| `random_each_run` | 每次运行重抽 |
| `override_mode` | 覆盖模式 |

输入槽中文名由 `INPUT_LABELS` 映射（`role_prompt` → 角色提示词），靠 socket label 显示。

专有名词保留英文：`JSON`、`danbooru`、档位键 `sfw` / `suggestive` / `explicit` / `hardcore` / `extreme`。

### 3.4 `IS_CHANGED`

```
覆盖文本为空 且 (seed < 0 或 random_each_run)  →  rand:<纳秒>（每次重抽）
覆盖文本非空 且 override_mode = 直通            →  SHA1(17 个参数)
其余情况                                        →  SHA1(17 个参数 + config_version)
```

- 哈希串包含 `role_prompt`，固定 seed 下改角色会重跑。
- `config_version` 来自 `settings.py`，只哈希 `settings` 段；只改收藏不改变它，因此不触发重跑。
- 覆盖直通不读档位配置，所以不纳入 `config_version`。
- `IS_CHANGED` 与 `run()` 都通过 `settings.snapshot()` 取同一份快照（按 `mtime_ns + size` 缓存），避免「哈希说变了、执行用旧值」。
- `run()` 中 `random_each_run` 开启且覆盖文本为空时，把 `seed` 强制为 `-1`。

## 4. 随机引擎

### 4.1 数据来源

| 文件 | 规模 | 字段 |
| --- | --- | --- |
| `data/tags.json` | 25 分类 / 2956 条 | `en` / `zh` / `lv`（0–4）/ `meta` |
| `data/scenes.json` | 45 个场景包 | `indoor` / `water` / `cold` / `time` 等标记 + 环境/服装/道具/姿势槽位 |
| `data/templates_ui.json` | 1800 套 | `id` / `index` / `bundle` / `kind` / `level` / `prompt` / `no_subject` |
| `data/tag_flags.json` | 418 条 | `tag → [indoor/outdoor/water/cold/night/monster]` |

> `index` 是「页码」（1–200，每页 9 套共用），不是唯一键；模板唯一键是 `id`。

### 4.2 分级与档位抽样

**词条分布**：Lv0 2308 → Lv1 56 → Lv2 322 → Lv3 259 → Lv4 11。
**模板分布**：6 个档位（sfw / suggestive / explicit / hardcore / extreme / any）各 300 套；其中普通 1200、异种 600。

档位分两层：

- **选择档位**：用户在 `level` 选的档，决定 `level` 输出口与负向词口径。
- **目标档位**：本次运行实际取词的上限，由 `settings` 抽样得到，**永远不高于选择档位**。

抽样规则：

| 选择档位 | 关闭「档位分布」总开关（默认） | 开启后（默认矩阵） |
| --- | --- | --- |
| `sfw` | 恒 Lv0 | Lv0 100% |
| `suggestive` | 恒 Lv1 | Lv1 50% / Lv0 50% |
| `explicit` | 恒 Lv2 | Lv2 50% / Lv0 25% / Lv1 25% |
| `hardcore` | 恒 Lv3 | Lv3 50% / Lv0–Lv2 各 ≈16.7% |
| `extreme` | 恒 Lv4 | Lv4 50% / Lv0–Lv3 各 12.5% |
| `any` | （v0.12 起不适用） | sfw 70% / 其余四档各 7.5% |

- 抽样粒度为**每次运行抽一次**：抽到哪档，整段提示词按该档取词，不是一条里混档。
- `any` 始终按配比执行，不受总开关影响；配比缺失或全 0 时回落 70 / 7.5×4。
- 候选池、`NSFW_COUNT`、`RATING_TAGS`、`tag_cap` 自动值、负向词全部按**目标档位**计算。
- `seed >= 0` 时抽样可复现。
- `level` 输出口仍返回**选择档位**的现有格式（`0 · 全年龄` / `any · 不限`）；目标档位与抽样依据写进 `report`。

### 4.3 人数与性向分档

- 默认基础主体是 `1girl solo`。
- 抽到需要两个人的姿势时主体切成 `2girls` 并补 `duo` 构图。
- 成人向词按单人 / 多人分别分档，不混用。
- 全库禁用男性词（`MALE_DENY`），命中即丢弃。

### 4.4 场景成套与现实逻辑

`scene_mode = 场景成套` 时，环境、服装、道具、姿势、光影来自**同一个场景包**，并由 `scenes.py` 做互斥校验：

- 室内包不出户外背景，反之亦然；
- 水域包才允许泳装与水中动作；
- 寒冷包不出泳衣、短袖；
- 夜景包才出夜景光影；
- 异性 / 异种只在 monster 线出现；
- 有角色时跳过内置外观抽取，也不把外观槽计入完整性校验（否则必然判为缺槽）。

`scene_mode = 自由随机` 则各槽位独立抽取，允许矛盾组合——这是刻意保留的模式。

### 4.5 覆盖优先级

```
template_override（直通）> role_prompt > role_mode=指定 > role_mode=随机
```

### 4.6 覆盖模式（v0.12 新增）

| 模式 | 行为 |
| --- | --- |
| `直通`（默认） | 覆盖文本非空 → 直接作为正向，完全跳过随机；负向按**选择档位**生成 |
| `混合` | 覆盖文本视为**锁定词条集**，其余槽位继续按目标档位随机 |

混合模式细则：

- 锁定词按英文 tag 去重，保持原顺序在最前；
- 随机结果与锁定词按英文 tag 去重，不重复；
- `tag_cap` 计入锁定词数量与质量前缀；锁定词已达上限时只输出锁定词；
- 锁定词在前、随机补充在后（Q7 的 MVP 顺序策略）；
- 直通模式下 `positive` 与覆盖文本逐字符一致（`extra_body` 仍追加）。

### 4.6.1 外观让位（v0.12.1）

角色输入非空时，两个开关决定哪些槽位不再随机：

| 开关 | 让位的槽位 | 适用 |
| --- | --- | --- |
| `appearance_follow`（默认开） | 发型 / 发色 / 面部 / 瞳色 / 身材 | 接了角色库节点，角色外观必须跟着提示词走 |
| `outfit_follow`（默认关） | 服装 / 配饰 | 角色节点勾了「输出服装」时打开 |

- 自由随机路径：直接跳过这些槽位，不消耗随机数。
- 场景成套路径：把这些槽位的权重置 0 —— `scenes.build` 见到 `b.on(key)` 为 False 就跳过完整性校验，不会误判缺槽重抽。
- 两个开关只在 `role_prompt` 非空时生效；关掉 `appearance_follow` 会让随机外观与角色官方设定冲突（这是开关的语义，不是 bug）。
- `report` 增加「让位槽位：…（交给角色输入）」。

### 4.7 角色提示词输入（v0.12 新增）

- 上游 STRING 连入 `role_prompt`，优先级高于 `role_name` / `role_works`。
- 拆分规则：按英文逗号拆分、去空格、忽略大小写去重。
- 位置：插在主体之后、发型/服装之前（自由随机走 `character` 槽，场景成套插在第一个非 subject 项之前）。
- 外部输入含主体词（`1girl` / `solo` / `2girls` / `duo` …）时**替换**默认主体，不会出现 `1girl, 1girl`。
- 性别策略：命中 `MALE_DENY` 的词条**直接丢弃**，其余保留；`report` 写「已拒绝 N 个男性词」。
- 默认不按档位过滤外部角色，`report` 标注「外部角色：未按档位过滤」。
- 直通模式下不参与生成，`report` 提示「角色输入未生效」。
- `report` 增加「角色来源：外部输入 / 词库 / 不指定」。

### 4.8 `report` 内容

```
选择档位: explicit · 成人
本次目标档位: Lv2 · 成人
抽样依据: 档位分布矩阵
已拒绝 1 个男性词              ← 仅在有外部角色词被拒时出现
外部角色: 未按档位过滤          ← 仅在有外部角色词时出现
场景: bedroom_night（场景成套，环境/服装/道具/姿势同一套）
标签: 27 个（主体 2 / 发型 1 / …）
角色来源: 外部输入
种子: 42
负面: 26 个
```

## 5. HTTP 路由

前缀 `/prompt_forge/`，7 条路径 / 9 个方法：

| 路由 | 方法 | 返回 |
| --- | --- | --- |
| `/library` | GET | `{cats:[{id,name,icon,tags:[{en,zh,lv,meta}]}]}`，全量 25 分类 |
| `/templates` | GET | `{total, items}`；支持 `?level=` `?kind=`（`all` 等同不过滤） |
| `/scene_meta` | GET | 45 个场景包的六个布尔标记 |
| `/scenes` | GET | `scenes.json` 全量（供场景页签） |
| `/tag_flags` | GET | `tag → 场景标记` 索引（供冲突检查） |
| `/roll` | GET | **弃用**，保留兼容：`?level=`（默认 sfw）、`?seed=`（默认 -1） |
| `/roll` | POST | 接收节点全参数 JSON，返回 `{positive,negative,level,report,target_level}` |
| `/userdata` | GET | `{favorites:{tags,templates,recent,zh}, settings:{...}}` |
| `/userdata` | POST | 原子写入；键名白名单；拒绝上三角非零矩阵 |

- 词库 / 模板 / 场景 / 索引首次请求后缓存在模块级 `_UI_CACHE`。
- 非 ComfyUI 环境（单元测试）下整块路由注册被 `try/except` 跳过，不抛异常。

### 5.1 `POST /roll` 请求体

```json
{
  "level": "sfw",
  "seed": -1,
  "tag_cap": 0,
  "base_prob": 0.65,
  "slot_weights": "",
  "role_mode": "none",
  "role_name": "",
  "role_works": "",
  "quality_prefix": "masterpiece, best quality",
  "artist_on": false,
  "negative_on": true,
  "extra_body": "",
  "scene_mode": "scene",
  "template_override": "",
  "override_mode": "direct",
  "role_prompt": ""
}
```

`level` / `scene_mode` / `override_mode` / `role_mode` 都接受内部键（`sfw` / `scene` / `direct` / `none`）；未知值回落到默认。

## 6. 前端工作台（v0.12）

### 6.1 加载方式

- `WEB_DIRECTORY = "./web"`，浏览器按 `/extensions/Comfyui-Prompt-Forge/<文件名>.js` 加载。
- `prompt_forge_v6.js` 做四件事：注册扩展 `PromptForge.WorkbenchV7`；在 `onNodeCreated` 追加按钮 `⚙ 打开提示词工作台`；把控件名与输入槽名映射为中文；拦截 `level` 切到 `any` 时唤起配比弹窗（`onConfigure` 期间用 `suppress` 标志屏蔽，加载工作流不弹窗）。
- `prompt_forge_core_v6.js` 是纯 UI 模块：不 import `app`/`api`，只通过 `globalThis.__pfFetch` 取数据，因此可在 `preview.html` 里单独跑。
- **`import "../../scripts/app.js"` 的路径相对 `web` 根解析**；把脚本放进 `web/js/` 会被解析成 `/extensions/scripts/app.js` 而 404，整个扩展失效。

### 6.2 面板结构

```
┌ 头部：⚙ Prompt Forge ｜ 🎛 自由选词 ｜ 🗂 模板卡片 ｜ 🏞 场景包 ｜ 类型筛选 ｜ 搜索 ｜ ↶ ↷ ⚙ ✕ ┐
├ 左：分类 / 场景分类            ├ 主区：胶囊 / 卡片 / 场景卡  ├ 右：已选词条 + 统计 + 冲突提示 ┤
│                               │                            │ 输出框 + 随机 / 清空            │
└───────────────────────────────┴────────────────────────────┴ 复制 / 写回 ┘
```

### 6.3 自由选词页

- 默认进入**第一个分类**（不再默认「全部」，首屏胶囊 ≤ 300）。
- 左侧固定三行：`全部` / `★ 收藏` / `◷ 最近`；分隔线后按 `tags.json` 原始顺序列出 25 个分类。
- 「全部」按每批 300 条分批渲染，底部「还有 N 条未渲染 · 点击继续加载」。
- 顶部 `☑ 中文对照` 开关；搜索同时匹配英文与中文，150ms 防抖。
- **不做档位屏蔽**：2956 条全部可选。
- 勾选写入 `template_override`，取消勾选同步删除；点选只重绘单个胶囊。
- 撤销 / 重做：20 步栈，清空 / 套用 / 单条增删都入栈；按钮与 `Ctrl+Z` / `Ctrl+Shift+Z`。
- 冲突检查：`tag_flags` 索引 + 白天词正则，检测室内+室外、水域+寒冷、夜景+白天、异种+非异种场景，**只提示不阻断**。
- 右下统计：`N 条 · 估算 T token`，`T = ceil(字符数 / 4)`；> 75 黄、> 150 红。

### 6.4 模板卡片页

- 顶部档位筛选条：`全部` + 数据里实际出现的档位（v0.12 是 6 个），每项带数量；选择存 `pf_tpl_level_v1`。
- 左侧场景分类：全部 / 室内 / 室外 / 夜景 / 寒冷 / 水域 / 异种；底部「只看我的收藏」。
- 顶部类型筛选：全部 / 普通 / 异种。

## 9.1 角色库（v0.1.1 新增）

### 9.1.1 节点

`AnimaCharacterPicker`，分类 `AnimaDecouple/Character`，输出 5 路：
`character` / `appearance` / `outfit` / `positive` / `report`。

四种选择模式：

| 模式 | 池子 | 说明 |
| --- | --- | --- |
| 随机 | 全库减排除名单 | 按 `(pop+1)^0.35 × 权重` 加权，压缩人气差异避免热门垄断 |
| 指定 | 单条 | `tag` → 英文名 → 中文名 → 模糊匹配 |
| 收藏随机 | 收藏减排除 | 至少一个收藏才有效 |
| 多选加权 | 勾选池减排除 | 权重 0.1–20 |

`work_filter` 只在「随机」模式生效，接受作品 id / 英文名 / 中文名，`|` 分隔。

### 9.1.2 三段拆分

`data/characters.json` 里每个角色是：

```json
{
  "tag": "hatsune_miku", "name": "hatsune miku", "zh": "初音未来",
  "work": "vocaloid", "trigger": "hatsune miku, vocaloid", "pop": 103500,
  "thumb": "hatsune_miku",
  "appearance": {
    "hair_color": ["aqua hair"],
    "hair_style": ["very long hair", "long hair", "twintails"],
    "eyes": ["aqua eyes", "blue eyes"]
  },
  "outfits": [{"id": "default", "zh": "官方服装", "level": 0,
               "tags": ["necktie", "sleeveless shirt", "black skirt"]}]
}
```

拆分规则（`tools/build_characters.py`）：

| 规则 | 结果 |
| --- | --- |
| `1girl` / `solo` 等 | 丢弃（主体由下游节点负责） |
| 含 `eyes` | 瞳色 |
| 含 `hair` 且含颜色词 | 发色 |
| 含 `hair` 不含颜色 | 发型 |
| 含 breasts / chest / waist 等 | 身材 |
| 含 freckles / mole / eyelashes 等 | 面部 |
| 匹配服装词表 | 服装 |
| 都不匹配 | **直接丢弃**（早期版本塞进 extras，导致 `crystal` 这类残渣进外观段） |

此外合并 `char_feat.json` 的人工核定固定特征（去掉与外观桶重复的）、
`char_hair_style.json` 的官方发型、`character_outfits.json` 的服装预设。

### 9.1.3 外观让位

角色节点的 `include_outfit` 与提示词节点的 `appearance_follow` / `outfit_follow`
配合，避免两套外观打架：

| 角色节点 | 提示词节点 | 结果 |
| --- | --- | --- |
| 外观开、服装关 | `appearance_follow=true` | 外观来自角色，服装随机 —— 推荐默认 |
| 外观开、服装开 | `appearance_follow=true` + `outfit_follow=true` | 外观服装全来自角色 |
| 外观关 | 任意 | 只有身份词，外观随机 |

### 9.1.4 面板与接口

7 个接口见 README。面板要点：

- 一次拉全量 `library`（1.16 MB），前端内存过滤，60 张一批渲染
- 缩略图走 `/anima_char/thumb/{tag}`，查找顺序：自定义 → `thumbs/*.webp` → `*.jpg` → `*.png`
  内置 2432 张是 webp；`fetch_thumbs.py` 补的用 jpg（系统 Python 没 Pillow，不转格式）
- 上传只收 webp（浏览器 canvas 先转一次，后端再用 RIFF/WEBP 魔数挡一道），≤ 4 MB
- 自定义角色存 `userdata/custom_characters.json`，同 `tag` 覆盖内置
- 状态存 `userdata/state.json`（与提示词的 `prompt_forge.json` 分开）

### 9.2 模板穿衣逻辑（v0.1.5）

`tools/fix_template_conflicts.py` 的三类判定，`validate_data.py` 复用同一份 `resolve()`：

| 冲突 | 判定 | 处理 |
| --- | --- | --- |
| 全裸 + 穿衣服 | `completely nude` / `nude` / `naked` 与 GARMENT 词表同时出现 | 删服装，**保留袜子与配饰**（`only socks` 是合法风格） |
| 裙装 + 裤子 | 一体式或半身裙与长裤/短裤同时出现 | 删裤子；`bikini + swim shorts` 这类泳装组合放行 |
| 上空 / 下空 | `topless` 与上装、`bottomless` 与下装同时出现 | 删对应半身服装 |

- `up skirt` / `skirt lift` / `dress lift` 是**动作词**，不参与判定 ——
  早期按裸词匹配导致「30 套冲突」的误报，实际只有 13 套真冲突。
- 修复后标签密度不受影响：中位数 29 → 28，最少 25，没有任何一套掉到 18 以下。

### 9.1.5 冒烟

`tools/routes_smoke.py` 用假 `PromptServer` / `aiohttp.web` 跑全部 16 个接口方法，
覆盖：注册完整性、路径穿越（`/thumb/../../__init__`）、非 webp 上传、空 tag、
内置角色拒绝删除、两个节点的输出。

## 11. trigger 校验（v0.1.8 新增）

`tools/verify_triggers.py`：查每个角色的 tag 在 booru 站上是否真实存在。

```bash
python tools/verify_triggers.py --only mihoyo      # 只查补充角色（快）
python tools/verify_triggers.py --all --workers 5  # 全量 2471 个
```

**为什么不用 danbooru**：`danbooru.donmai.us` 在本机连不上（Cloudflare / 链路），
改用 `safebooru.org` 的 dapi 查「这个 tag 有多少帖子」，`count > 0` 即存在。

**两个踩过的坑**：

1. **必须用 `c["tag"]` 查，不能用 `trigger` 的第一段。**
   `trigger` 是给人看的简写（`ganyu`），站点 tag 表里只有规范写法
   `ganyu_(genshin_impact)`。拿简写去查会全部返回 0 ——
   第一版就栽在这，2471 个里报了 529 个「查不到」，抽样复核后 100% 查得到。

2. **并发别开太高。**
   6 线程 + 0.3 秒间隔时热门角色（甘雨 / 芙宁娜）也会返回 0，
   是站点的限速假阴性。实际用 4–5 线程、失败重试 3 次比较稳。

报告写到 `data/_trigger_report.json`，字段 `{tag, zh, trigger_tag, count}`。

## 12. animadex.net（v0.1.9 接入）

`https://animadex.net` 是比 safebooru 好用得多的数据源，本插件用它做两件事：
查角色 / 画师的规范 tag，取角色缩略图。

### 接口（Flask，返回 JSON）

| 接口 | 说明 |
| --- | --- |
| `GET /api/characters/search?q=&limit=&page=` | 角色搜索，返回 `{total, page, pages, results[]}` |
| `GET /api/artists/search?limit=&sort=liked` | 画师搜索（15879 个） |
| `GET /api/copyrights/search?limit=` | 作品搜索 |
| `GET /api/<mode>/facets` | 分面：character / copyright / hair_color / hair_length / eye_color / gender |
| `GET /api/<mode>/facet/<name>` | 单个分面的取值与计数 |
| `GET /thumb/<mode>/<slug>` · `GET /img/<mode>/<slug>` | 缩略图 / 原图 |

### 角色记录字段

```json
{
  "slug": "hatsune_miku", "name": "Hatsune Miku",
  "copyright": "vocaloid", "copyright_name": "Vocaloid",
  "trigger": "hatsune miku, vocaloid",
  "tags": ["1girl", "aqua eyes", "very long hair", "aqua hair", "twintails"],
  "count": 103500,
  "thumb_url": "https://blobs.animadex.net/Outputs/thumbs/hatsune%20miku%2C%20vocaloid.webp",
  "img_url": "https://blobs.animadex.net/Outputs/hatsune%20miku%2C%20vocaloid.png"
}
```

`slug` 就是 danbooru 的规范 tag（`mavuika_(genshin_impact)`），
`trigger` 是空格写法（`mavuika (genshin impact), genshin impact`）——
两者别混用：查站点用 slug，写提示词用 trigger。

### 用它修出的 7 个错误 tag（v0.1.9）

之前手写的补充角色里有 7 个 tag 拼错了，在 animadex 上逐个核对后改正：

| 原写法 | 正确写法 | 说明 |
| --- | --- | --- |
| `liliya_(honkai_impact)` | `liliya_olenyeva` | 用全名 |
| `griseo_(honkai_impact)` | `griseo` | 无后缀 |
| `vill-v_(honkai_impact)` | `vill-v` | 无后缀 |
| `timido_cang` | `timido_cute` | 是 Cute 不是 Cang |
| `tesla_(honkai_impact)` | `frederica_nikola_tesla` | 用全名 |
| `carole_pepper` | `carole_peppers` | 复数 |
| `aloy_(genshin_impact)` | `aloy_(horizon)` | 归到地平线，不是原神 |

### 限制

- **有速率限制**：5 并发 + 0.2 秒间隔会触发 429，实际用 1–2 线程、1 秒间隔。
- **每页最多 36 条**：`limit=1000` 也只返回 36，全量 36488 个角色要翻 1014 页，
  所以只适合按 tag / 关键字查询，不适合批量导出。
- 缩略图是 webp（约 17 KB），原图是 PNG（几百 KB）。
