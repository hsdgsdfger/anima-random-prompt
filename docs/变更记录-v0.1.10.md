# 本次改动说明（v0.1.9 之上的补丁）

> 目标：**先把"看得见的慢"和"会出错的逻辑"修掉**，不改数据结构、不改接口路径、不改控件顺序。
> 所有改动都在干净副本上验证过：`validate_data.py` / `selftest_v012.py` / `routes_smoke.py` 三个自检全过。

---

## 一、怎么用

### 方式 A：打补丁（推荐，仓库是 git 装的）

```bash
cd ComfyUI/custom_nodes/Comfyui-Prompt-Forge
git apply /路径/优化补丁-v0.1.9.patch
```

补丁已经用 `git apply --check` 在原始提交 `1c6aba2` 上验证过，**不会冲突**。

### 方式 B：直接覆盖文件

把 `补丁文件/` 里的 6 个文件按同名位置覆盖进插件目录：

```
补丁文件/__init__.py                     -> Comfyui-Prompt-Forge/__init__.py
补丁文件/engine.py                       -> Comfyui-Prompt-Forge/engine.py
补丁文件/scenes.py                       -> Comfyui-Prompt-Forge/scenes.py
补丁文件/char_state.py                   -> Comfyui-Prompt-Forge/char_state.py
补丁文件/web/prompt_forge_core_v6.js     -> Comfyui-Prompt-Forge/web/prompt_forge_core_v6.js
补丁文件/tools/routes_smoke.py           -> Comfyui-Prompt-Forge/tools/routes_smoke.py
```

> `tools/routes_smoke.py` 只是自检脚本（假 aiohttp 升级了一下），**不影响插件运行**，可以不覆盖。

### 装完要做的事

1. **重启 ComfyUI**（后端路由改了，必须重启）。
2. 浏览器里按 `Ctrl + F5` 强制刷新一次（前端 JS 有缓存）。

### 回滚

```bash
git apply -R /路径/优化补丁-v0.1.9.patch     # 撤销
# 或者
git checkout -- .                            # 全部还原到仓库当前提交
```

## 二、改了什么（按收益排序）

### 1. 缩略图对不上号（58.8% 角色没有预览）—— 已修

**改法**：`__init__.py` 的 `/anima_char/thumb/{tag}` 加了一层映射：先拿 tag 去角色库查记录里的 `thumb` 字段，再用它去磁盘找文件；找不到再退回用 tag 本身（自定义上传的图仍按 tag 存，所以照旧能命中）。

**验证**（用真实 tag 跑一遍路由）：

| | 改前 | 改后 |
|---|---|---|
| 能取到缩略图 | 1 002 / 2 432（41.2%） | 2 461 / 2 471（99.6%） |
| 取不到的 10 个 | — | 都是米哈游补充角色里那批**源站本来就没有图**的（`varesa_` / `lan_yan_` 等） |

顺带给预览图加了缓存头：
- 内置图：`Cache-Control: public, max-age=31536000, immutable`
- 自定义图：`no-cache`（重传后能立刻看到新图）

效果：第二次打开角色库，60 张图基本都从浏览器缓存直接出，不再重复下载。

**前端不需要改**（仍然用 tag 拼 URL，服务端负责映射），所以老页面缓存也不会出问题。

---

### 2. 大接口：预序列化 + gzip + ETag —— 已改，首屏从约 2.5 MB 降到约 380 KB

**根因**：每次打开面板，后台都要把 1.2 MB 模板、1.1 MB 角色库重新 `json.dumps` 一遍再发；浏览器拿到的还是明文。

**改法**（`__init__.py` 新增 `_json_resp()`）：把响应体算一次，存成 `原始字节 + gzip 字节 + ETag`；之后：
- 有 `Accept-Encoding: gzip` → 直接吐压缩字节（不再编码）；
- 相同 ETag → 返回 `304`，一个字节都不传；
- 不支持 gzip 的客户端 → 自动回退明文（已验证）。

**实测（本机跑真实数据）**：

| 接口 | 改前 | 改后（gzip） | 压缩比 | 缓存命中耗时 |
|---|---|---|---|---|
| `/prompt_forge/templates` | 1 181.3 KB | **140.6 KB** | 88% | 0.6 ms |
| `/anima_char/library` | 1 120.1 KB | **188.1 KB** | 83% | 0.7 ms |
| `/prompt_forge/library` | 172.6 KB | **40.8 KB** | 76% | 0.1 ms |
| `/prompt_forge/scenes` | 44.4 KB | **8.0 KB** | 82% | 0.1 ms |
| `/prompt_forge/tag_flags` | 14.2 KB | **2.8 KB** | 80% | 0.1 ms |
| **打开工作台合计** | **≈ 2 531 KB** | **≈ 380 KB** | **−85%** | — |

另外：装库/角色库/场景/冲突索引这几个**大字典不再常驻内存**（序列化完就释放，进程里只留压缩字节），后台常驻内存也降了一截。

> 注意：模板列表本身仍留在内存（因为要支持 `?level=` / `?kind=` 过滤），这部分约 3–4 MB 没有动。

---

### 3. 模板缓存不失效（加了自己模板要重启）—— 已修

模板列表改成按三个文件的 `(mtime, size)` 指纹缓存：`data/templates_ui.json`、`data/templates_v6.json`、`userdata/templates_extra.json`，任一文件变了就重读。

**验证**：运行中往 `userdata/templates_extra.json` 加 1 套 → 总数 1937 → **1938**（无需重启）；删掉 → 回到 1937。

---

### 4. `slot_weights` 三个老问题 —— 已修

| 问题 | 改前表现 | 改后 |
|---|---|---|
| 值写成非数字（`{"clothing":"high"}`） | 自由随机路径 **直接 ValueError 崩掉**（场景路径反而正常） | 回落到默认权重 1.0，正常出词，且结果与不填权重一致 |
| `{"nsfw":0}` 想关掉成人向 | **两条款不生效**，成人向照出 | 自由/场景两条路径都真的关掉（实测成人向槽 1 条 → **0 条**） |
| `{"monster":...}` 写错类型 | 场景路径 `float()` 崩 | 安全回落 |

---

### 5. 标签超上限时"砍错了地方" —— 已修

**根因**：超上限时先按 `drop_order` 删可选槽，再 `flat[:cap]` 从**尾部**硬截；而拼装顺序末尾正好是 `monster → nsfw → rating`，于是最先被切的恰恰是评级词和成人向词。

**改法**：新的 `_trim_to_cap()`：评级词、成人向词、主体、角色**永不剪**；先保质量前缀和手写补充，再从"最不重要的槽位"（道具/天气/构图/镜头）开始让位，还有空位就按"重要度高→低"回填。

**验证（`level=extreme`，手动把 `tag_cap` 调小，各 12 次）**：

| tag_cap | 改前 缺评级词 | 改前 缺成人向 | 改后 缺评级词 | 改后 缺成人向 |
|---|---|---|---|---|
| 14 | **12 / 12** | **12 / 12** | 0 / 12 | 0 / 12 |
| 20 | 1 / 12 | 1 / 12 | 0 / 12 | 0 / 12 |
| 24 | 0 / 12 | 0 / 12 | 0 / 12 | 0 / 12 |

> 默认 `tag_cap=0`（自动 28/32）时，这个 bug 基本不触发，所以我另外做了"默认参数下改前改后比对"，见下一节。

---

### 6. 场景包最多重抽 60 次 —— 降到 12 次

场景包自带 7 条互斥校验，不合格整包重抽。原来是 60 轮，极端配置下单次排队会被拖住；12 轮已足够，失败直接退回自由随机（本来就有这条兜底）。正常配置下行为不变。

---

### 7. 角色节点每张图都 `fsync` 写盘 —— 已去掉强制刷盘

`char_state.save_state()` 加了 `sync` 参数。面板改收藏仍走 `fsync`（保证不丢），节点每次出图只为更新"最近用过谁"，改成普通写入（原子替换还在，不会写坏文件）。

---

### 8. 面板"随机一份"和直接排队结果不一致 —— 已修

`_roll_from()` 以前没接 `appearance_follow` / `outfit_follow` 两个参数，前端那个骰子按钮也没传。现在两边都补齐了。

---

### 9. 路由注册失败不再静默

原来整段 16 个路由包在 `except Exception: pass`：任何一个注册失败，**它后面的路由会全部凭空消失**，前端只显示"加载失败"。现在改成打印失败原因，日志里能看到真话。

---

### 10. 前端两处热点（不改外观，只降 CPU）

| 改动 | 原来 | 现在 |
|---|---|---|
| 档位筛选条的计数 | 每个档位跑一遍全表（6 个档位 = 6 次 × 1 937 条），每次切分类/搜索都重算 | 一次遍历算出全部档位 + 按筛选条件签名缓存；筛选判断抽成 `tplPass()` 与筛选逻辑共用一份 |
| 已选词条的高亮 | 每颗胶囊都做一次 `selected.includes`（胶囊 × 已选） | 每次重绘建一个 `Set`，O(n) 查找 |
| 收藏/最近页签 | 每次重绘都建 2 956 条的 `tag → 记录` Map | 只在真用到时才建 |

## 三、出图结果受影响吗？

我把 240 组参数（6 档 × 场景/自由 × 20 个 seed）在改前/改后各跑一遍，比对 `positive + negative` 的哈希：

- **229 / 240 完全逐字节相同**
- **11 组不同**（占 4.6%），全部是"场景成套 + 正好卡在标签上限"的情况
- 差异性质：**标签总数一模一样，只是某一个同槽位的可选词换了个人**（例如 `treasure chest` 换成 `crystal ball`，都是道具槽）
- **没有任何一组变短**；评级词 240/240 齐全（改前也是）

也就是说：**默认用法下 95% 的结果不变，剩下 5% 只是"哪个道具词被留下"变了**，这正是第 5 条修复的副作用（不再从尾部乱切）。

如果你的工作流依赖"某个 seed 出的那一张图"，把这 5%的差异当成改版即可，不要拿旧 seed 去对齐。

## 四、这次**没**改的（需要你拍板，或留到第二批）

| 项目 | 为什么先不动 |
|---|---|
| 前端卡片窗口化（只渲染屏幕内 40 张） | 收益大，但要改渲染骨架，**没有真机可测**，容易把卡片交互弄坏；建议你先试这版，确认没别的问题我再动 |
| 角色库拆"索引 + 详情"（1.1 MB → 0.45 MB） | 要改 3 个面板函数（选人/信息条/编辑器都依赖 `appearance`+`outfits`），属于中等风险改造；gzip 已经把下行压到 188 KB，先吃这波红利 |
| 合并"两本演员名册"（1 401 vs 2 432） | **会改变出图结果**，且要统一匹配规则，必须先有你认可的标准答案 |
| `appearance_follow=关` 时是否仍注入官方外观 | 现在两者并存（官方 + 随机），这是**语义决策**，不是纯 bug |
| 每张图只写一次"最近"这点 IO 已处理，但状态文件仍每次写 | 再进一步要改成内存累积、定时落盘，收益小、出错面大 |
| 版本号（5 处不一致） | 属于发布流程问题，改了会和你现有构建脚本打架；建议定一个"版本只有一处定义"的规则后再动 |
